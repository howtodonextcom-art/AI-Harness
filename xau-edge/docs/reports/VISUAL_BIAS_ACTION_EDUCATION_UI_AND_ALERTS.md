## 2. Design decision that departs from the brief

The brief puts BIAS above ACTION. The earlier TRADE-08 blind A/B (4 reviewers, 20 screenshots) found that a big "↑ MUA" before or beside CHỜ read as "buy, wait", and that an amber hero read as a warning. So: the hero keeps the action first and neutral; the new BIAS and ACTION pair sits directly under it, side by side, with equal weight, and amber is used on the ACTION chip and on blockers, not on the whole hero. The brief's own rule (never render the whole hero green while WAIT) is kept.

## 4. Colour system

Green = BUY direction context (BUY permission only when the label says MUA PAPER and the ticket exists). Red = SELL direction context; ✕ SL and system errors carry their own icon and text, never colour alone. Amber = WAIT, caution, execution blocker. Blue = HOLD, informational (M30 "i"). Grey = neutral, not evaluated, unavailable. Intensity ladder: bias is a light tint with a left edge, setup a medium tint, READY a solid fill. Every state has an icon and a word; the cards have aria-labels. Borders and tints are used rather than saturated fills (dark mode keeps the `dark:` text colours).

## 5. Backend contract (the server owns the semantics)

`why_wait.diagnostic` now carries `bias {side, source, reading, reason}`, `formation {state: NO_SETUP | FORMING | WAITING_TRIGGER | READY, bars_since_armed}`, `blockers[]`, `execution {spread_points, spread_percentile and limit, spread_to_atr_m5 and limit, volatility_regime, atr_m15, atr_percentile and minimum, m1_state}`, `rows[]` with PASS / FAIL / NOT_EVALUATED, `primary_blocker`, `primary_stage`, `also_missing`. It is computed from the recorded decision state; `decide` still stops at the first refusal and `refusal_reasons` stay the only authorization. Thresholds shown are the `StateConfig` defaults. Contract goldens were regenerated from the real engine.

## 8. Remaining gaps (honest)

- **Chrome DevTools MCP coverage is PARTIAL**: the live page, console and Lighthouse were checked through MCP; the other states (SELL bias, READY, HOLD, EXIT, armed) were checked through Playwright screenshots of the real-engine goldens, not by driving the MCP browser through the replay stack. 960x720 was not captured.
- **Event timeline** (BIAS BUY, SETUP ARMED, WAITING TRIGGER, BUY READY, POSITION FILLED, TP/SL) is not built as a single visual list; the existing lifecycle strip and last-event line remain.
- **Alerts**: `PAPER_FILLED` added; SETUP_ARMED and SETUP_EXPIRED alerts, bias alert and critical failures into the same channel are still missing (they need the owner's channel and wording choice). Telegram is not configured, so delivery is the file fallback.
- Execution thresholds in the card are the `StateConfig` defaults, not read from a runtime override (none exists today).
- The Entry / SL / TP "tooltip on hover" for blockers is shown inline instead of in a hover popup, which is more reliable for keyboard and touch users.
