# Chart readability and CSS audit (2026-10-11)

Trigger: the owner compared `/trade` with the FTMO MT5 web terminal and found the candles too small and the screen hard to read, and asked where the CSS comes from.

## 1. Where the CSS comes from (evidence from the browser)

| Part | Source |
|---|---|
| Buttons, cards, text, layout | **one** compiled stylesheet, `/_next/static/chunks/0spldwncxgcgw.css`, generated by **Tailwind CSS 4** from `app/globals.css` (`@import "tailwindcss"`, custom variants `short` and `roomy`) through the turbopack rule in `next.config.ts` (`@tailwindcss/turbopack`). `document.styleSheets` shows exactly that file plus one inline style tag. |
| Fonts | Geist and Geist Mono, self-hosted woff2 files served from `/_next/static/media/*` by `next/font` (`app/layout.tsx`). Body font: `Geist, "Geist Fallback", system-ui, sans-serif`. |
| Colours of page and dark mode | CSS variables `--background` and `--foreground` in `globals.css`, switched by `prefers-color-scheme`. |
| **The candle chart** | **not CSS.** It is canvas drawn by lightweight-charts v5 (`document.querySelectorAll('canvas')` gives the plot, price scale and time scale canvases). Candle colours (`#16a34a`, `#dc2626`), grid, text colour, price scale, bar spacing and session bands are set in JavaScript in `components/terminal/TerminalChart.tsx` and `lib/sessions.ts`. |

So a CSS change could not have fixed "the candles are small"; it was a chart-configuration problem.

## 2. Comparison and diagnosis

FTMO was opened in the MCP browser but stops at its login form; it was not logged into and nothing on it was touched. FTMO numbers are therefore read from the owner's screenshot (approximate, by eye): candles fill about 70% of the plot height, about 100 candles in view, about 12 px per candle.

Measured on `/trade` before the fix (build `86338bf`, M1, structure, key levels and sessions on, canvas pixel analysis):

| | FTMO (screenshot) | `/trade` before |
|---|---:|---:|
| candle span / plot height | about 0.70 | **0.196** (M5: 0.31) |
| bars in the first view | about 100 | **409** |
| px per candle | about 12 | **2.3** |

Two causes, both in `TerminalChart.tsx`:

1. **Price scale stretched by context lines.** The autoscale provider added every price line except manual levels, alerts and key levels, so PDH, PDL, M15 RES, M15 SUP (and TP2) stretched the scale to 4131-4207 while the candles sat at 4194-4196.
2. **First view fitted the whole history.** `fitContent()` showed all 400 loaded bars.

Not causes (checked): chart container height (608 px), the session bands (a legibility issue only, lightened), the volume pane.

## 3. Options, criteria fixed before coding

Criteria: candle span at least 40% of the plot by default; at least 6 px per candle in the first view; plan and position levels always inside the scale; a context level never shrinks the candles but stays reachable; no change to strategy or backend; measurable by a test.

A. exclude all context lines from the scale. B. include a context line only if near the candles (within half of the candles' own range). C. fixed padding. A loses nothing but also never shows a near level fully; C does not solve it. Chosen **B** (plan and position lines always in, TP2 counts as context), plus a first view sized to the width (about 9 px per candle, 40 to 160 bars) instead of the whole history.

## 4. Implementation

- `lib/chartScale.ts` (pure): `scaleRange`, `defaultWindowBars`; `TerminalChart.tsx` uses them (always-in-scale ids: ENTRY, SL, TP1, PAPER ENTRY/SL/TP, NOW).
- Session bands lightened (alpha 0.045 to 0.07 instead of 0.07 to 0.11).
- Context items in the legend are smaller and dimmer; on a chart narrower than 520 px they fold into "+N mức ngữ cảnh" (still in the DOM for screen readers).
- The session legend moved above the time axis (it covered the time labels).
- Commits `8422ecc`, `7f71881`, `d4351b4`. Nothing in the backend, strategy or any gate changed.

## 6. Tests

- `e2e/unit/chart_scale.spec.ts` (6) and `e2e/chart_readability.spec.ts` (5): far levels do not shrink candles (span at least 0.4 and at least 6 px per candle on M1 and M5), a live plan stays inside the scale, the session legend clears the time axis, the phone legend does not eat the chart. Mutation check: setting the context reach to 1000 made the span test fail at 0.05.
- Full Playwright mock suite **362 / 362**, real-backend acceptance **31 / 31**, `tsc` and `eslint` clean, on `d4351b4`. No Python change, so the earlier backend gate (2834 passed) still applies.

## 7. Remaining

- On a phone with M5 and all layers the candles fill 47% (above the 40% criterion, under FTMO's 70%): a near level (PDH) still joins the scale.
- A manual Entry/SL/TP far from price (a live plan on M1) still stretches the scale: that is the contract (the plan is always visible), not a defect.
- FTMO numbers are approximations from a screenshot because the terminal needs a login.
